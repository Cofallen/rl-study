# rl-course 环境说明与修复记录

> 目标：`00-环境/main.py` 全部 OK，且不影响 isaac / mjlab / GPTSoVits 等其他 conda 环境。
> 日期：2026-11-10（第二次修订：发现 VS Code 终端的 `PYTHONNOUSERSITE=1` 才是主因）

## 结论

在**两种**终端下都跑通了 13/13：

| 场景 | 结果 |
|------|------|
| VS Code 集成终端（`PYTHONNOUSERSITE=1`，也就是你现在这个终端） | **13/13** |
| 普通终端（user-site 开启） | **13/13** |

关键变化：**rl-course 现在是自包含的**，不再借用 `~/.local` 里的包。

## 为什么你看到 6/13，而我最早报的是 13/13

你的 VS Code 设置里给集成终端注入了环境变量（`~/.config/Code/User/settings.json`）：

```json
"terminal.integrated.env.linux": {
    "OMNI_KIT_ACCEPT_EULA": "Y",
    "PYTHONNOUSERSITE": "1",          // ← 关闭“用户级 site-packages”
    "__NV_PRIME_RENDER_OFFLOAD": "1",
    "__GLX_VENDOR_LIBRARY_NAME": "nvidia",
    "__VK_LAYER_NV_optimus": "NVIDIA_only"
}
```

而 `rl-course` 这个环境里，有相当一部分包**根本不在环境里，而是在 `~/.local/lib/python3.10/site-packages`**
（GPT-SoVITS 时期装到用户目录的，isaac / GPTSoVits 两个 3.10 环境也会看到它）：

```
~/.local 里的：scipy  matplotlib  pandas  tqdm  regex  numba  librosa
              + transformers/datasets 的一堆传递依赖：pyyaml filelock fsspec
                protobuf httpx anyio h11 lxml ...
rl-course 里的：numpy torch gymnasium transformers datasets peft accelerate trl
```

你的终端一关 user-site，这些包全部消失，于是：

- `matplotlib / scipy / tqdm` → 直接 MISSING；
- `transformers` 卡在 `import regex` → MISSING；
- `datasets`（要 pandas/tqdm）、`peft`/`accelerate`（要 transformers）→ 连带 MISSING；
- `trl` 恰好是懒加载，所以单独 OK。

我最早用 `conda run` / `bash -lc` 跑，不经过 VS Code，user-site 是开的，所以看到 13/13 —— 那是假象。

## 顺带修掉的那个误导性报错（只在 user-site 开启时出现）

报错说 `ModuleNotFoundError: Could not import module 'BloomPreTrainedModel'`，其实 Bloom 是存在的，真实链路：

```
peft → transformers 懒加载 Bloom → modeling_layers → processing_utils
     → audio_utils → import librosa（~/.local 的 0.9.1）
     → from pkg_resources import resource_filename
     → setuptools 84 已经删掉 pkg_resources  ❌
```

再往里还有一层：transformers 5 的 `audio_utils.py` 假定“有 librosa 就一定有 soxr”（老 librosa 带的是 resampy）。

## 具体改了什么（全部在 rl-course 环境内）

| # | 改动 | 原因 |
|---|------|------|
| 1 | `setuptools` 84.2.1 → **80.10.2** | 80.x 是最后一个带 `pkg_resources` 的版本 |
| 2 | 新装 `soxr==1.1.0` | transformers 5 在 librosa 可用时强制 `import soxr` |
| 3 | 把原来只在 `~/.local` 的包**装进环境** | 让环境自包含，关掉 user-site 也能用 |

第 3 条装进去的：`matplotlib 3.10.9`、`scipy 1.15.3`、`pandas 2.3.3`、`tqdm 4.68.2`、`regex 2026.5.9`、
`seaborn 0.13.2`、`scikit-learn 1.7.2`、`absl-py`、`joblib`、`protobuf`、`httpx`、`sacrebleu`、
`platformdirs`、`lxml`、`portalocker`、`tabulate`、`threadpoolctl`，以及它们的小依赖
（`pyyaml filelock fsspec anyio h11 httpcore jinja2 rich typer ...`）。

`python-dateutil` 固定为 **2.9.0**（最新的 3.0.0 会让 `botocore` 报冲突）。

## 以后装包时的一个坑

VS Code 终端虽然关掉了 user-site 的**运行时**加载，但 `pip` **解析依赖时仍然看得见 `~/.local`**，
于是会把那里的包当成“已安装”而跳过。要确保包装进环境本身：

```bash
PYTHONNOUSERSITE=1 pip install <包名>
```

（或者 `pip install --ignore-installed <包名>`）。这就是我第一次 `pip install matplotlib ...` 看起来成功、
实际什么都没进环境的原因。

## 注意事项

1. **不要在 rl-course 里升级 setuptools**（`pip install -U setuptools`）—— `pkg_resources` 会再消失，
   普通终端（user-site 开）下 peft 会重新报 `BloomPreTrainedModel`。
2. 课程官方钉的是 `transformers==4.57.3 / trl==0.24.0 / datasets==4.4.1 / accelerate==1.10.1`，
   当前是 5.20.2 / 1.14.2 / 5.2.0 / 1.15.0。前 7 章（CartPole → PPO）用不到这几个；
   跑到第 8 章（RLHF）以后如果示例代码报 API 不匹配，再按 `code/chapterXX/requirements.txt` 钉版本。
3. 无头跑 MuJoCo 环境记得 `export MUJOCO_GL=egl`。
4. 不建议去掉 VS Code 里的 `PYTHONNOUSERSITE=1` —— 它对 isaac 等环境是种保护；现在 rl-course 自包含，不需要它让步。

## 回滚

```bash
conda activate rl-course
pip install "setuptools==84.2.1"
pip uninstall -y soxr
# 第 3 条（补装的那些包）不回滚也不影响其他环境；要回到“半依赖 ~/.local”的状态，逐个卸载即可
```
